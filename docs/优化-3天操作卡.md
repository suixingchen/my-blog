# my-blog 优化 · 3 天操作卡

> 前提：你只做 **登录权限 + 评论** 两件事 + 一点界面美化。
> 规则：**每一步都只看这一小节**，做完立刻验证，验证通过再翻下一节。
> 遇到报错先自己查 30 分钟，然后把「完整报错 + 你改的文件内容 + 你的猜测」发给我。

## Day A · 加登录（约 1.5–2 小时）

### 为什么先做这个

现在 `/admin` 谁都能进 —— 这是评委一眼能看出来的硬伤。加了 Security 之后你可以讲：
过滤器链怎么工作、密码为什么不能明文存、CSRF 是什么、哪些页面该放行。

### ⚠️ 开始前必须知道的三件事（不然一定卡）

1. **加完依赖后，默认全站都要登录** —— 包括你的首页！所以必须配放行规则，否则博客变成"打开就是登录页"。
2. **CSRF 会拦掉你的后台表单** —— 新建/编辑/删除都会 403，因为表单没带 CSRF token。这是初学者必踩的坑，下面第 4 步专门处理。
3. **H2 控制台会打不开** —— 它用了 frame，需要单独放行并关掉 frameOptions。

### 步骤 1：加依赖（2 分钟）

打开 `pom.xml`，在 `spring-boot-starter-validation` 那个依赖**下面**粘贴：

```xml
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-security</artifactId>
        </dependency>
```

保存后，让 VS Code 重新加载项目（右下角提示点 `Load`，或者关掉重开）。

**验证**：项目能编译（没有红色波浪线）。

---

### 步骤 2：新建配置类（15 分钟）

新建文件 `src\main\java\com\example\blog\config\SecurityConfig.java`，内容：

```java
package com.example.blog.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.provisioning.InMemoryUserDetailsManager;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    /** 密码加密器：数据库里绝不存明文密码 */
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    /** 先用内存里的一个管理员账号，不建用户表 */
    @Bean
    public UserDetailsService userDetailsService(PasswordEncoder encoder) {
        UserDetails admin = User.withUsername("admin")
                .password(encoder.encode("admin123"))
                .roles("ADMIN")
                .build();
        return new InMemoryUserDetailsManager(admin);
    }

    /** 核心：哪些页面放行、哪些要登录 */
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/css/**").permitAll()          // 样式放行
                .requestMatchers("/", "/article/**").permitAll() // 前台放行
                .requestMatchers("/h2-console/**").permitAll()   // H2 控制台放行
                .requestMatchers("/admin/**").hasRole("ADMIN")   // 后台要登录
                .anyRequest().authenticated()
            )
            .formLogin(form -> form.permitAll())                 // 用默认登录页
            .logout(logout -> logout.logoutSuccessUrl("/"))       // 退出后回首页
            .csrf(csrf -> csrf.ignoringRequestMatchers("/h2-console/**"))
            .headers(h -> h.frameOptions(f -> f.sameOrigin()));   // 让 H2 控制台能显示
        return http.build();
    }
}
```

**验证**（先别管表单，这步只验证"拦截 + 登录"）：

1. 启动项目（用的是 `D:\c++\my-blog\start-blog.cmd` 里同一套命令，或者 VS Code 里点 Run）
2. 浏览器打开 `http://localhost:8081` → **首页应该正常显示**（放行了）
3. 打开 `http://localhost:8081/admin` → **跳到登录页**
4. 输入 `admin` / `admin123` → **进到后台**

到这一步就成功一半了。

### 步骤 3：加"退出"按钮（5 分钟）

登录之后你会发现**没有退出入口**（默认登录页才有）。在后台列表页加一个。

打开 `src\main\resources\templates\admin\list.html`，找到这一段：

```html
        <a class="btn btn-primary" th:href="@{/admin/articles/new}">+ 写新文章</a>
```

在它**下面**加：

```html
        <form th:action="@{/logout}" method="post" style="display:inline">
            <input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}" />
            <button type="submit" class="btn">退出登录</button>
        </form>
```

**验证**：刷新后台页面 → 出现「退出登录」→ 点它 → 回到首页，再访问 `/admin` 又要求登录。

---

### 步骤 4：给表单加 CSRF token（这一步不做，后台就写不了文章）

CSRF 会拦掉所有 POST 表单。要修两个地方。

**位置 1**：`src\main\resources\templates\admin\form.html`
找到 `<form class="card form-card" th:object="${articleForm}"` 这行下面的 `<form ...>` 开标签，在开标签**下面紧跟**加一行：

```html
        <input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}" />
```

**位置 2**：`src\main\resources\templates\admin\list.html`
找到删除用的那个表单 `<form th:action="@{/admin/articles/{id}/delete(id=${article.id})}" method="post"`，
也在开标签下面加同样的那一行：

```html
                        <input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}" />
```

**验证（关键，四条都要过）**：

- [ ] 登录后点「写新文章」→ 填标题正文 → 保存成功（不是 403 错误页）
- [ ] 编辑一篇文章 → 保存成功
- [ ] 删除一篇文章 → 确认后删除成功
- [ ] 点「退出登录」→ 回首页 → `/admin` 又要登录

如果哪一步出现 **403 Forbidden**，就是某个表单漏了那行 token。

## Day B · 加评论（约 45 分钟）

用 **Giscus**：把 GitHub Discussions 当评论区，**零后端、零数据库**，代码只有一段 script。

### 步骤 1：开启仓库的 Discussions（2 分钟）

浏览器打开 `https://github.com/suixingchen/my-blog` → **Settings** → 找到 **Features** → 勾选 **Discussions**。

> 你的仓库是 public，Giscus 正好需要这个。

### 步骤 2：生成配置代码（5 分钟）

1. 打开 https://giscus.app/zh-CN
2. 「仓库」填 `suixingchen/my-blog` → 它会让你**安装 giscus app**，点授权（只给这一个仓库即可）
3. 「Discussion 分类」选 `Announcements`（或 `General`）
4. 「页面 ↔️ discussion 映射关系」选 **pathname**（每个 URL 一个评论区）
5. 往下滚，复制生成的 `<script ...>` 那一整段

### 步骤 3：贴到文章详情页（5 分钟）

打开 `src\main\resources\templates\article.html`，找到文章卡片结束的位置（大概是 `</article>` 之前的 `article-foot` 那段之后），把那段 script 粘进去。

建议放在「继续阅读」区块**之前**，并用一个卡片包一下：

```html
        <section class="card">
            <h4 class="card-title">评论</h4>
            <!-- 把 giscus.app 生成的那段 <script> 整段粘在这里 -->
        </section>
```

**验证**：
- [ ] 打开任意文章页 `http://localhost:8081/article/1`，滚到底能看到评论框
- [ ] 点「使用 GitHub 登录」能正常跳转（说明配置对）

**这一步能讲的东西**：为什么不自研评论（维护成本、垃圾评论、登录体系）——这是"技术选型"的加分回答。

## Day C · 界面小美化 + 笔记 + 演示准备（约 1.5 小时）

### 1. 暗色模式（20 分钟，性价比最高）

打开 `src\main\resources\static\css\style.css`，在**文件最末尾**追加：

```css
/* ===== 暗色模式：跟随系统设置 ===== */
@media (prefers-color-scheme: dark) {
    :root {
        --bg: #0f1115;
        --card: #171a21;
        --text: #e6e8eb;
        --muted: #9aa4b2;
        --border: #262b34;
        --accent: #6c9bff;
    }
    .article-content { color: #d7dbe0; }
    .summary { color: #b8c0cb; }
    .tag, .page-link { background: #1d222b; }
}
```

**验证**：把 Windows 系统设置里的"深色/浅色模式"切换一下，刷新页面看效果。

> 能讲：为什么用 CSS 变量 + `prefers-color-scheme`（零 JS、跟随系统）。

### 2. 正文排版微调（10 分钟，可选）

同一个文件里找到 `.article-content`，把 `font-size` 调到 `16px`、`line-height` 调到 `1.9`，读起来更舒服。

### 3. 写笔记（30 分钟，这是评委真正看的）

按这个结构写 3 段就够：

```markdown
## 我给博客加了登录

### 做了什么
引入 Spring Security，只有 /admin 需要登录，前台保持公开。

### 卡在哪（必须写真实的）
- 加完依赖后首页也变成登录页 → 原因是默认全站拦截 → 用 permitAll() 放行
- 后台表单提交全部 403 → 原因是 CSRF → 给表单补 hidden token

### 学到了什么
- 密码不能明文存，用 BCrypt 加密
- CSRF 是"防止别人伪造你的请求"
```

### 4. 演示脚本（15 分钟）

写死你要演示的顺序，演示时照着念：

1. 首页列表 → 搜索 → 分类筛选
2. 点进一篇文章 → 看到阅读量、标签、评论区
3. 直接访问 `/admin` → **被拦到登录页**（这是最直观的亮点）
4. 登录 → 发一篇新文章 → 编辑 → 删除
5. 退出登录
6. 打开笔记，讲 2 个你踩过的坑

## 必答清单：评委一定会问的 6 个问题

**这是最危险的部分**——这个项目不是你自己从零敲的，所以你必须能答上来，否则一问就露。

| 问题 | 你要能答出的要点 |
|---|---|
| 1. 你的项目分几层？为什么这么分？ | Controller（收请求）/ Service（业务规则）/ Repository（只管数据）/ 模板（显示） |
| 2. 访问 `/article/1` 时代码怎么走？ | 请求 → Controller 收到 id → Service 查库 → 放 Model → 返回模板名 → Thymeleaf 渲染 |
| 3. 为什么加 Spring Security？ | 后台原来谁都能进；现在 `/admin/**` 要 ADMIN 角色，前台放行 |
| 4. CSRF 是什么？你怎么处理的？ | 别人伪造你的请求；每个表单带一个服务端签发的 token |
| 5. 你的阅读量怎么加的？并发会有问题吗？ | 简单实现：查到 +1 再保存；并发下可能少加，可以改成 `UPDATE ... SET views = views + 1` |
| 6. **现场加一个字段**（最狠） | 实体加 `author` → 表单加输入框 → 详情页显示 → 重启（`ddl-auto=update` 自动加列） |

**第 6 题一定要自己在家练两遍**，它是"自己写的"和"抄的"的分水岭。练熟了你就有底气说"这是我做的，我可以现场改"。

---

## 关于"这是你自己写的吗"这个风险

我不替你撒谎，给你三条实话策略：

1. **别说是自己从零敲的**。可以说"我参照一个开源实现搭起来，然后自己改的"——评委对"能改、能讲"的认可度远高于"从零敲但讲不清"。
2. **把改动做成真的**：上面这两个功能（登录、评论）确实是你按步骤改的，这就是你的改动，讲它们最踏实。
3. **准备一个"我踩过的坑"故事**：CSRF 那个坑非常典型，讲出来比任何功能都有说服力。
