## 0. 一页纸看懂整个项目

```
浏览器请求
   │
   ├─ Spring Security 过滤器链 ── 先判断"这个人能不能访问这个地址"
   │      ├─ 没登录 + 访问 /admin/** ──→ 重定向到 /login
   │      ├─ 已登录 ──→ 放行，并把"当前用户"放进 SecurityContext
   │      └─ 表单 POST ──→ 校验 CSRF token，不对就 403
   │
   ├─ Controller ── 接收参数、决定返回哪个页面
   │      ├─ HomeController      首页列表（分页/搜索/分类）
   │      ├─ ArticleController   详情页（阅读量+1、评论列表）
   │      ├─ CommentController   发表/删除评论
   │      ├─ AdminController     后台文章增删改查
   │      ├─ AdminSettingController 更换壁纸
   │      ├─ LoginController     登录页
   │      └─ ThemeCssController  动态生成 /theme.css
   │
   ├─ Service ── 业务规则（发布状态、级联删除评论、文件校验…）
   │
   ├─ Repository ── 数据读写（Spring Data JPA，方法名自动生成 SQL）
   │
   ├─ MySQL 数据库（article / comment / site_setting 三张表）
   │
   └─ Thymeleaf 模板 ── 把数据渲染成 HTML 返回给浏览器
```

**面试时可以这样开场**：

> 这是一个 Spring Boot + Thymeleaf + JPA + MySQL 的个人博客。前台能看文章列表和详情，
> 后台能发文章、管评论、换壁纸，后台加了登录验证。
> 代码分 Controller / Service / Repository 三层，用 Maven 构建，Git 分了 10 次提交，全部推在 GitHub 上。

## 1. 数据存储：从 H2 换成 MySQL

### 涉及文件

| 文件 | 作用 |
| --- | --- |
| `src/main/resources/application.yml` | 数据源配置（MySQL 连接串、账号密码、JPA 设置） |
| `src/main/resources/application-h2.yml` | 备用配置：没有 MySQL 时用 H2 |
| `src/main/java/.../entity/Article.java` | 文章实体，决定表结构 |

### 关键配置逐行解释

```yaml
datasource:
  url: jdbc:mysql://localhost:3306/blog?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
  driver-class-name: com.mysql.cj.jdbc.Driver
  username: root
  password: "123456"
jpa:
  hibernate:
    ddl-auto: update      # 启动时自动建表/加列（开发期用；生产该改成 none + 迁移脚本）
  open-in-view: false     # 不在视图渲染阶段持有数据库连接
```

- **`serverTimezone`**：不写会报时区错误；
- **`allowPublicKeyRetrieval=true`**：MySQL 8 默认用 `caching_sha2_password`，非 SSL 连接需要这个参数才能完成认证；
- **`ddl-auto: update`**：只加不改不删，**不会**自动删你的数据，但也**不能**用来改字段类型（这就是我踩的坑，见下）；
- **`open-in-view: false`**：避免"Controller 返回后数据库连接还开着"的隐患，逼着你在 Service 里把数据取完。

### 我踩的坑（很值得讲）

内容字段一开始是这样写的：

```java
@Lob
@Column(nullable = false)
private String content;
```

在 H2 上没问题（映射成 CLOB），但换到 MySQL 后启动就崩：

```
Data truncation: Data too long for column 'content' at row 1
```

我进数据库看表结构，发现 `content` 被建成了 **`tinytext`（最大 255 字节）** —— Hibernate 用 `@Lob` 加默认长度 255 推断出了一个极小的类型，而示例文章正文有 300 多字。

**修法**：显式给出长度 `@Column(nullable = false, length = 65535)`，这样 MySQL 生成 `text`（65KB），H2 生成 CLOB，两边都够用。改完还要把旧表删掉让它重建（`ddl-auto=update` 不会改已存在的列类型）。

> 这件事的通用教训：**`ddl-auto` 只适合开发期**，字段类型变更、重命名这类操作在生产必须用迁移工具（Flyway / Liquibase）脚本化。

### 另一个坑：方言别写死

我原本写了 `database-platform: org.hibernate.dialect.MySQLDialect`，结果单元测试全挂——`@DataJpaTest` 会把数据源换成内嵌 H2，但方言仍是 MySQL，于是生成 `engine=InnoDB` 这种 H2 不认的 DDL。**删掉这行，让 Hibernate 按实际连接自动判断方言**，App 连 MySQL 用 MySQL 方言、测试连 H2 用 H2 方言，两边都对。

### 可能被问

1. **为什么用 MySQL 又留 H2？**
   → MySQL 是交付形态，贴近真实环境；H2 是备用（没装 MySQL 的机器上 `--spring.profiles.active=h2` 直接能跑），同时也让单元测试能用内嵌数据库，不依赖外部服务。
2. **`ddl-auto` 有哪些值？生产用什么？**
   → `none / validate / update / create / create-drop`。生产用 `none`（或 `validate`）+ Flyway 脚本，因为 update 不会改已有列、也无法回滚。
3. **表是怎么建的？**
   → Hibernate 根据 `@Entity` 和字段注解生成 DDL（文章表 = `article`，字段名驼峰转下划线：`createdAt` → `created_at`）。

## 2. 登录验证：Spring Security

### 涉及文件

| 文件 | 作用 |
| --- | --- |
| `pom.xml` | 加 `spring-boot-starter-security`、`thymeleaf-extras-springsecurity6` |
| `config/SecurityConfig.java` | **核心**：密码加密器、管理员账号、访问规则 |
| `controller/LoginController.java` | 只负责把登录页显示出来 |
| `templates/login.html` | 自定义登录页（和博客同风格） |
| `templates/fragments/layout.html` | 页头按登录状态显示"账号+退出"或"登录" |
| `templates/admin/form.html`、`admin/list.html` | 表单里补 CSRF token |

### 三块代码，面试就讲这三块

**① 密码怎么存**

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

BCrypt 是**加盐哈希**：同一个密码每次加密结果都不同，数据库泄露也没法反推出原密码。

**② 账号从哪来**

```java
@Bean
public UserDetailsService userDetailsService(PasswordEncoder encoder) {
    UserDetails admin = User.withUsername("admin")
            .password(encoder.encode("admin123"))
            .roles("ADMIN")
            .build();
    return new InMemoryUserDetailsManager(admin);
}
```

现在是一个内存管理员账号；**如果要扩展成多用户**，把这个 Bean 换成查数据库的 `UserDetailsService` 实现即可，其它代码一行不用改 —— 这是 Spring Security 的设计好处（面向接口）。

**③ 谁能访问什么**

```java
http.authorizeHttpRequests(auth -> auth
        .requestMatchers("/css/**", "/uploads/**", "/favicon.ico").permitAll()   // 静态资源
        .requestMatchers("/", "/article/**", "/login", "/theme.css").permitAll() // 前台 + 登录页
        .requestMatchers("/admin/**").hasRole("ADMIN")                           // 后台要 ADMIN
        .anyRequest().authenticated()                                            // 其余都要登录
)
.formLogin(form -> form.loginPage("/login").defaultSuccessUrl("/admin", true).permitAll())
.logout(logout -> logout.logoutSuccessUrl("/").permitAll())
.csrf(csrf -> csrf.ignoringRequestMatchers("/h2-console/**"))
.headers(h -> h.frameOptions(f -> f.sameOrigin()));
```

**规则是从上往下匹配，第一条命中就生效**（顺序写反会把前台也拦住）。

### 三个必须能讲的细节

**① 为什么每个表单都要加这一行？**

```html
<input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}" />
```

这行的作用是 **CSRF 防护**。CSRF（跨站请求伪造）是指：你登录了博客，然后打开了攻击者的网页，那个网页偷偷向你的博客提交了一个"删除文章"的表单 —— 浏览器会自动带上你的登录 Cookie，服务器以为是你要删。

Spring Security 的防法：每个表单必须携带一个**服务端签发的随机 token**，攻击者的网页拿不到这个 token，提交就会被拒（403）。所以加登录后我第一件事就是给后台三个表单补 token。

**② 退出为什么是 POST？**

```html
<form th:action="@{/logout}" method="post">
```

Spring Security 6 默认要求退出用 POST 且带 CSRF token。原因一样：如果是 GET，攻击者放一个 `<img src="/logout">` 就能把你踢下线。

**③ 登录的用户名代码里怎么拿到？**

```java
@PostMapping("/article/{articleId}/comments")
public String addComment(..., Authentication authentication, ...) {
    commentService.add(articleId, authentication.getName(), text);
}
```

`Authentication` 由 Spring Security 自动注入，`getName()` 就是登录用户名。**这就是"登录"和"业务"的连接点。**

### 我踩的坑

加完依赖后**首页也变成登录页了** —— 因为默认行为是"全站拦截"。必须显式写 `permitAll()` 放行前台。这个坑几乎每个初学者都会踩，能讲出来很加分。

### 可能被问

1. **密码存在哪里？明文吗？**
   → 不存明文。现在账号在内存里，密码是 BCrypt 加密后的字符串；换成数据库也是存这个哈希值。
2. **用户登录状态怎么保持的？**
   → 登录成功后 Spring Security 把认证信息放进 `SecurityContext`，默认存在 **HttpSession** 里，浏览器靠 `JSESSIONID` Cookie 关联。
3. **会话固定攻击（Session Fixation）考虑过吗？**
   → Spring Security 默认就会在登录成功后更换 SessionID（`changeSessionId`），我用的就是默认策略。
4. **怎么限制只有管理员能删评论？**
   → 删除路径写成 `/admin/comments/{id}/delete`，落在 `/admin/**` 规则下，非 ADMIN 直接被拦；前端按钮也用 `sec:authorize="hasRole('ADMIN')"` 隐藏。

## 3. 评论功能

### 涉及文件

| 文件 | 作用 |
| --- | --- |
| `entity/Comment.java` | 评论表结构 |
| `repository/CommentRepository.java` | 查询/统计/按文章删除 |
| `service/CommentService.java` | 业务规则（发表、列表、删除、级联清理） |
| `controller/CommentController.java` | 发表评论、删除评论两个接口 |
| `templates/article.html` | 评论区（表单 + 列表 + 删除按钮） |
| `test/.../CommentServiceTest.java` | 4 个单元测试 |

### 表设计：为什么不用 `@ManyToOne`

```java
@Column(name = "article_id", nullable = false)
private Long articleId;
```

评论属于某篇文章，最"正统"的写法是 `@ManyToOne Article article`（外键对象关联）。我选了**普通 Long 字段**，理由说清楚就加分：

1. 页面只需要"评论内容 + 作者 + 时间"，不需要从评论反查整篇文章对象；
2. 避免懒加载异常（`LazyInitializationException`）和 N+1 查询这两类经典坑；
3. 代价是**删文章时要自己删评论** —— 我在 `ArticleService#delete` 里显式调用了 `commentRepository.deleteByArticleId(id)`，避免留下孤儿数据。

（如果面试官问"那级联删除怎么做"，答：JPA 关联上用 `cascade = CascadeType.REMOVE`，或数据库外键 `ON DELETE CASCADE`，我这里是应用层显式删除，最直观。）

### 数据流（一定要能背下来）

**发表评论**：

1. 用户在详情页填内容 → 点提交 → `POST /article/1/comments`（表单里带 `content` 和 `_csrf`）
2. Spring Security 先验 CSRF、再验是否登录（没登录直接 302 到 `/login`）
3. `CommentController.addComment()` 拿到 `articleId`（路径变量）、`content`（表单字段）、`authentication`（当前用户）
4. 校验：空内容/超 500 字 → 带着错误提示重定向回去
5. `CommentService.add()` → `commentRepository.save()` → 插入 `comment` 表
6. `redirect:/article/1#comments` 重定向（Post/Redirect/Get，刷新不会重复提交）
7. 重新渲染详情页时，`ArticleController` 已经把评论列表放进了 Model，`article.html` 用 `th:each` 渲染

**删除评论**（管理员）：`POST /admin/comments/{id}/delete` → 先查评论拿到 `articleId` → 删除 → 重定向回那篇文章的评论区。

### 可能被问

1. **评论和文章怎么关联的？**
   → `comment.article_id` 存文章 id，查询用 `findByArticleIdOrderByCreatedAtDesc`，Spring Data 按方法名自动生成 SQL，不用手写。
2. **为什么评论按时间倒序？**
   → 最新评论放最上面，符合阅读习惯；排序写在方法名里（`...OrderByCreatedAtDesc`）。
3. **怎么防垃圾评论？**
   → 现在有三层：必须登录、内容非空且限长 500、管理员可删。要更强可以加频率限制（同一用户 N 秒一条）、敏感词过滤、或者接 Giscus 这类第三方。
4. **删文章时评论怎么办？**
   → `ArticleService#delete` 里先 `deleteByArticleId` 再删文章，注释里写明了原因；单元测试 `deletingArticleAlsoDeletesItsComments` 专门守着这条规则。

## 4. 背景壁纸（自主更换）

### 涉及文件

| 文件 | 作用 |
| --- | --- |
| `entity/SiteSetting.java` | 单行配置表（id 固定为 1），存壁纸路径 |
| `service/SiteSettingService.java` | 上传校验、保存、删除旧文件、恢复默认 |
| `controller/AdminSettingController.java` | 设置页 + 上传 + 恢复默认 |
| `controller/ThemeCssController.java` | **把壁纸生成为动态 CSS** |
| `config/WebMvcConfig.java` | 把 `uploads/` 目录暴露成 `/uploads/**` |
| `templates/admin/settings.html` | 设置页（预览 + 上传表单） |
| `templates/fragments/layout.html` | 引入 `/theme.css` |

### 核心思路：壁纸是"数据"，不是"配置"

一开始我把它想成配置文件里的一个路径，但那就得改文件+重启，谈不上"自主更换"。所以：

- **存数据库**：`site_setting` 表只有一行（id=1），字段 `bg_image` 存 `/uploads/xxx.png`；
- **存文件**：图片落在项目下 `uploads/`（已加进 `.gitignore`，用户上传的东西不进仓库）；
- **生效**：`/theme.css` 由后端读数据库动态生成，模板里只是引用它。

### 上传功能的三个安全点（面试高频）

```java
// ① 不信任原文件名：UUID 重命名，杜绝 ../../ 路径穿越
String filename = UUID.randomUUID().toString().replace("-", "") + "." + ext;
// ② 校验后缀白名单 + 大小（大小上限从 application.yml 读，不在代码里写死）
if (!ALLOWED_EXT.contains(ext)) throw new IllegalArgumentException("只支持 jpg/png/gif/webp");
if (file.getSize() > maxSize) throw new IllegalArgumentException("图片不能超过 " + maxSizeLabel);
// ③ 数据库只存相对路径（/uploads/xxx.png），换机器也能用
```

另外 `deleteOldFile()` 里还检查了路径必须以 `/uploads/` 开头且不含 `..`，防止被构造出删除任意文件的请求。

### 把"大小上限"做成只配置一处

上限最初在三个地方各写了一遍：`application.yml` 的 multipart 配置、Service 里的常量、页面上的文案。
想把 5MB 调到 40MB 就得改三处，漏一处就会出现"页面写着 40MB、传个 20MB 还是失败"的怪事。

现在只保留一份配置：

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 40MB        # 单个文件真正的上限
      max-request-size: 45MB     # 整个请求体（还含表单其他字段），留一点余量
```

Service 直接读同一个配置，代码里不再出现数字：

```java
public SiteSettingService(SiteSettingRepository siteSettingRepository,
                          @Value("${spring.servlet.multipart.max-file-size:40MB}") String maxFileSize) {
    DataSize limit = DataSize.parse(maxFileSize);          // "40MB" -> 41943040 字节
    this.maxSize = limit.toBytes();
    this.maxSizeLabel = limit.toMegabytes() + "MB";        // 页面显示用的 "40MB"
}
```

页面上的"不超过 40MB"也不是写死的：`GlobalModelAdvice` 往每个页面注入 `maxUploadSize`，
模板里写 `th:text="'...不超过 ' + ${maxUploadSize} + '）'"`。以后调上限只改 yml 一个数字。

### 超过上限时用户看到什么

Tomcat 在读请求体时就把超大文件拦下了，异常抛出点在 Controller 方法执行**之前**，
所以 Controller 里的 `try-catch` 根本接不到——一开始用户看到的是白底的 500 错误页。

解决办法是在全局异常处理里接住并跳回设置页：

```java
@ExceptionHandler(MaxUploadSizeExceededException.class)
public String handleUploadTooLarge(MaxUploadSizeExceededException ex, HttpServletRequest request) {
    log.warn("上传文件超过大小上限，请求 {} 被拒绝: {}", request.getRequestURI(), ex.getMessage());
    return "redirect:/admin/settings?tooLarge=1";   // 设置页根据这个参数显示人话提示
}
```

还有一个容易漏的配置：Tomcat 默认 `max-swallow-size: 2MB`，超限时只肯读完 2MB 请求体就断开连接，
浏览器有时看到的是"连接被重置"而不是我们的提示页。所以 `application.yml` 里设成 `-1`（不限），
让请求完整读完，友好提示才能正常返回。

### 为什么单独搞一个 `/theme.css`

我一开始想在 Thymeleaf 模板里直接拼 CSS，结果连踩两个坑，页面直接 500、请求还被重定向到登录页（现象很迷惑）：

1. `th:inline="css"` 的内联语法必须写成 `/*[[${...}]]*/` 注释形式，写成 `[[...]]` 会报 `SpelParseException`；
2. 改成 `th:text` 拼一长串 CSS，仍然报 `Unexpected data after '.'` —— 因为 **CSS 选择器里的点（`.card`）被 SpEL 当成属性访问**。

**最终方案**：后端生成 CSS（`ThemeCssController`），模板里只留 `<link rel="stylesheet" href="/theme.css">`。好处：

- 模板里零表达式，不可能再出这类解析错误；
- 换壁纸不重启、不改模板，刷新即可；
- 逻辑集中在 Java 里，可测试、可调试。

> 这段经历非常适合讲，因为它体现了"**遇到模板层的坑，换一个更稳的架构切面**"的工程判断，而不是死磕。

### 可能被问

1. **上传的文件为什么浏览器能访问？**
   → Spring Boot 默认只暴露 classpath 下的 `static/`。我在 `WebMvcConfig` 里注册了资源处理器：`/uploads/**` → `file:项目目录/uploads/`，把磁盘目录映射成 URL。
2. **图片存数据库还是存文件系统？**
   → 现在存文件系统、数据库只存路径。理由：图片是二进制大对象，放数据库会让备份和查询变重；真要统一管理可以用对象存储（MinIO / OSS）。
3. **怎么防止有人上传 .jsp / .exe？**
   → 后缀白名单 + 内容类型检查 + 用 UUID 重命名（原文件名不会出现在磁盘上，即使上传了可执行文件也没法通过 URL 直接执行）。

### 站点改名：数据库优先、配置兜底

需求：站名和作者名要能在网页上改，不能每次改 `application.yml` 再重启；
但**不能把已有文章里写好的作者字段一起改掉**。

做法是复用 `site_setting` 这张单行表，加两个可空字段：

```java
@Column(name = "site_title", length = 100)
private String siteTitle;      // null = 用 application.yml 的 blog.title

@Column(name = "site_author", length = 100)
private String siteAuthor;     // null = 用 application.yml 的 blog.author
```

读取时"数据库优先、配置兜底"：

```java
public String getSiteTitle() {
    return siteSettingRepository.findById(SiteSetting.SINGLETON_ID)
            .map(SiteSetting::getSiteTitle)
            .filter(value -> value != null && !value.isBlank())
            .orElse(defaultSiteTitle);        // 构造器注入的 ${blog.title}
}
```

三个值得讲的设计判断：

1. **为什么放数据库不放配置文件**：站名是"管理员会改的数据"，改配置要重启；放数据库保存即生效。
2. **为什么"留空 = 恢复默认"**：`normalizeName()` 把空串当 `null`，读取时自然回落到默认值，
   不需要额外做一个"恢复默认"按钮。
3. **为什么不同步到文章**：`article.author` 是写作时的业务数据（这篇文章是谁写的），
   而站名是"站点身份"。两者不该耦合，所以 `updateNames()` 只写 `site_setting`，
   一条 SQL 都不碰 `article` 表。

页面模板一行没改：`GlobalModelAdvice` 里 `${blogTitle}` / `${blogAuthor}` 的来源
从"配置文件注入"换成"调用 service"，模板照样用这两个名字。

**可能被问**：

- 改站名要重启吗？→ 不用。值在数据库里，下一次渲染就取到新的（Thymeleaf 缓存也是关的）。
- 加了字段数据库表会自动变吗？→ `ddl-auto: update` 会自动加列，但**不会**改已有列的类型；
  生产环境该用迁移脚本（Flyway / Liquibase），我在文档里也写了这一点。

## 5. 首页排版与卡片配色（前端体验）

### 需求怎么来的

原来首页是"标题 + 搜索 + 文章列表"三块堆在一起，壁纸被卡片挡得只剩边角。
改成：**首屏整屏只显示壁纸**（站名 + 一句"向下滑动"），往下滚才进文章区；
卡片改成半透明毛玻璃，壁纸能透出来但字还看得清；侧边栏加「外观」，让读者自己挑配色。

### 涉及的 5 个文件

| 文件 | 干什么 |
| --- | --- |
| `templates/index.html` | 首屏结构：`<section class="hero-full">` + `<main id="posts">` |
| `templates/fragments/layout.html` | ① head 里提前读 localStorage ② 侧边栏「外观」三块色板 |
| `static/css/style.css` | 三套配色变量、毛玻璃卡片、首屏、淡入动画、手机端 |
| `static/js/reading.js` | 切换配色 + 存 localStorage + 下滑淡入 |
| `controller/ThemeCssController.java` | 壁纸从 body 背景改成固定图层 |

### 核心思路：配色只改 CSS 变量

一套主题就是几个变量，卡片规则一行都不用动：

```css
:root {                                   /* 默认「雪白」 */
  --card-bg: linear-gradient(150deg, rgba(255,255,255,.94), rgba(222,235,255,.80));
  --card-border: rgba(255,255,255,.70);
  --card-blur: 14px;
}
html[data-card="sand"] {                  /* 「暖砂」 */
  --card-bg: linear-gradient(150deg, rgba(255,250,242,.94), rgba(255,209,160,.82));
}
html[data-card="pine"] {                  /* 「雾松」 */
  --card-bg: linear-gradient(150deg, rgba(240,252,248,.94), rgba(190,226,246,.82));
}

.card, .post-card {
  background: var(--card-bg);
  backdrop-filter: blur(var(--card-blur)) saturate(140%);
}
```

JS 只做一件事：往 `<html>` 上贴 `data-card="sand"`，再存进 localStorage：

```js
root.setAttribute('data-card', theme);          // CSS 立刻换配色
localStorage.setItem('blog.cardTheme', theme);  // 下次打开还记得
```

★ 这就是**设计令牌（design token）**：颜色不散落在几十条规则里，集中成变量。
以后要加第四套配色，只需要再加一段 `html[data-card="xxx"] { ... }`，别的都不用碰。

### 三个容易忽略的细节（面试可以主动讲）

**① 闪屏问题**：如果等 JS 跑完再上色，进页面会先白一下再变暖砂。
所以 `layout.html` 的 head 里放一段内联脚本，**在样式应用之前**就把 `data-card` 贴好。

**② 壁纸不画在 body 上**
原来用 `background-attachment: fixed`，它在 iOS Safari 上有兼容问题、滚动也容易卡。
改成固定图层：

```css
body::before {
  content: '';
  position: fixed;
  inset: 0;
  z-index: -1;                       /* 躺在所有内容下面 */
  background-image: url('/uploads/xxx.png');
  background-size: cover;
  background-position: center;
}
```

**③ 脚本挂了不能白屏**
淡入靠 `.reveal { opacity: 0 }`，万一 JS 没跑起来，文章就永远看不见。两道保险：

```css
.js .reveal { opacity: 0; }          /* 只有 JS 可用时（head 里加 .js）才隐藏 */
```

```js
if (!('IntersectionObserver' in window)) { /* 老浏览器：全部直接显示 */ }
window.setTimeout(revealInViewport, 1200);  /* 兜底：1.2 秒后再补一次 */
```

### 可能被问

- **配色为什么存浏览器不存数据库？** 这是"这台设备上读者的偏好"，管理员不该替访客决定；
  存 localStorage 不用加接口、不用改表。
- **`backdrop-filter` 兼容性怎么办？** 不支持时用 `@supports not (...)` 把卡片调成接近实色，保证能读。
- **首屏为什么用 `100svh`？** `100vh` 在手机浏览器上会把地址栏算进去，导致内容跳动；
  `100svh` 是"最小可视高度"，更稳，同时保留 `100vh` 给老浏览器兜底。
- **无障碍考虑了吗？** 系统开"减少动态效果"时关掉动画；色板是 `<button>` + `aria-pressed`，
  键盘也能操作。

### 第 4 套配色「夜墨」：深色主题为什么不能只改背景色

浅色卡片换成深色卡片，**文字颜色也得跟着翻**，否则就是"深底黑字"，一个字都看不清。
所以第一步是把所有颜色抽成变量，让一套主题 = 覆盖一组变量：

```css
:root {                        /* 浅色（默认） */
  --text: #1f2329;             --muted: #7b8794;
  --content-text: #2b3038;     --text-soft: #495057;
  --surface: #ffffff;          --badge-bg: #eef3ff;
  --ok-bg: #f0fbf3;            --danger-soft-bg: #fff5f5;
}
html[data-card="ink"] {        /* 夜墨（深色）：只覆盖变量 */
  --card-bg: linear-gradient(150deg, rgba(30,37,52,.92), rgba(16,21,33,.84));
  --text: #e9effb;             --muted: #9fb0c9;
  --content-text: #dde5f4;     --text-soft: #ccd7e9;
  --surface: rgba(255,255,255,.07);  --badge-bg: rgba(96,138,250,.24);
  --accent: #7aa7ff;           /* 深底上蓝色要提亮，不然发灰 */
}
```

做完这件事还有个隐藏收益：**深色模式几乎没写新规则**，全靠变量被覆盖。
这也是"为什么不要到处写死颜色"最有力的例子——面试可以直接讲。

### 字号 / 行距：把排版也做成变量

```css
:root { --content-size: 16.5px; --content-leading: 1.95; }
html[data-font="sm"] { --content-size: 15px; }
html[data-font="lg"] { --content-size: 18.5px; }
html[data-leading="loose"] { --content-leading: 2.25; }

.article-content { font-size: var(--content-size); line-height: var(--content-leading); }
```

JS 那边和配色完全是同一套机制：`data-font` / `data-leading` 两个属性 + 两个 localStorage 键。
**三种设置共用一套"贴属性—存本地—按钮高亮"的代码**，没有写三遍。

### 沉浸模式与一个真实的坑

沉浸模式就是给 `<html>` 加 `data-immersive="on"`，CSS 收起侧边栏：

```css
html[data-immersive="on"] .sidebar { display: none; }
html[data-immersive="on"] .layout  { grid-template-columns: minmax(0, 1fr); }
```

**坑**：侧边栏被收起了，用户就找不到开关退出来，所以必须有出口按钮。
我最初把出口按钮写成一个 `position: fixed` 的悬浮按钮，放在页头里面——结果它跑到页头右上角了。
原因：**页头有 `backdrop-filter`，而 `filter` / `backdrop-filter` / `transform` 会让元素成为
`position: fixed` 子元素的"包含块"**，于是 `fixed` 不再是相对视口定位。
最后的做法是把按钮直接放进导航栏（普通流式布局），既不会跑位，也一直可见。

### 用 URL 参数直接指定外观

`/?card=ink&font=lg&leading=loose&immersive=on` 可以一次指定全部设置（会顺手存进 localStorage）。
好处是不用点四次就能演示/截图，也方便把"我这套配色"发给别人。

## 6. 数据库里的三张表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `article` | id, title, summary, content(text), category, tags, author, views, published, created_at, updated_at | 文章。`published=false` 是草稿，前台不展示 |
| `comment` | id, article_id, author, content, created_at | 评论。按 article_id 查、按文章级联删 |
| `site_setting` | id(固定1), bg_image, updated_at | 站点外观设置，只有一行 |

**时间戳统一由 `@PrePersist` / `@PreUpdate` 自动维护**（文章创建时间在 `Article.onCreate()` 里设置），业务代码不用手写，也不会漏。

## 9. 五分钟速记版（面试前最后看一眼）

- 三层结构：Controller 收请求 → Service 业务规则 → Repository 数据访问
- 登录：BCrypt 存密码、内存账号、`/admin/**` 要 ADMIN、表单带 CSRF token、退出用 POST
- 评论：`article_id` 普通字段关联、按文章查询、删文章先删评论、必须登录才能评
- 壁纸：`site_setting` 单行表存路径 → `/theme.css` 动态生成 → `uploads/` 映射成静态资源
- 上传安全：UUID 重命名 + 后缀白名单 + 40MB 大小限制 + 只存相对路径
- 踩过的坑：MySQL `tinytext`（`@Lob` 默认长度）、方言写死导致测试挂、Security 默认全站拦截、CSRF 403、Thymeleaf 拼 CSS 报 SpEL 错误
